## 🔴 CRITICAL

### SEC-001 · Unsafe Deserialization (`pickle.loads`)
- **File:** `src/user_service.py` line 41  
- **Issue:** `pickle.loads(data_bytes)` deserializes arbitrary caller-supplied bytes. A crafted payload executes arbitrary OS commands during deserialization — no authentication required.  
- **Fix:** Replace `pickle` with `json`. If binary serialization is required, use HMAC-signed payloads and validate the schema before loading.

### SEC-002 · Command Injection (`subprocess.call(shell=True)`)
- **File:** `src/user_service.py` line 37  
- **Issue:** `subprocess.call("python reports/" + report_name, shell=True)` passes user input directly to a shell. Injecting `;` or `&&` executes arbitrary host commands.  
- **Fix:** Use `subprocess.run(["python", f"reports/{report_name}"], shell=False)` and whitelist valid report filenames.

### SEC-003 · Info Disclosure — Unauthenticated `/debug` endpoint exposes all secrets
- **File:** `src/api.py` lines 50–57  
- **Issue:** The `/debug` GET endpoint is unauthenticated and returns the DB password, API key, and JWT secret in plaintext JSON.  
- **Fix:** Remove the endpoint. Health checks should return only `{"status": "ok"}` behind authentication.

## 🟠 HIGH

### SEC-004 · SQL Injection — `get_user` string concatenation
- **File:** `src/user_service.py` line 20  
- **Issue:** Username is concatenated directly into a SQL string. Classic `' OR '1'='1` bypass possible.  
- **Fix:** `cursor.execute("SELECT * FROM users WHERE username = ?", (username,))`

### SEC-005 · SQL Injection — `create_user` `%`-format string
- **File:** `src/user_service.py` lines 48–51  
- **Issue:** Python `%`-formatting builds the INSERT statement from user-supplied values.  
- **Fix:** `cursor.execute("INSERT INTO users (username, password, email) VALUES (?, ?, ?)", (username, hashed, email))`

### SEC-006 · SQL Injection — `update_user_email` string concatenation
- **File:** `src/user_service.py` lines 59–60  
- **Issue:** `new_email` is concatenated into the UPDATE string; `user_id` cast provides no SQL safety.  
- **Fix:** `cursor.execute("UPDATE users SET email = ? WHERE id = ?", (new_email, user_id))`

### SEC-007 · Hardcoded Secrets — DB password and API key in source
- **File:** `src/user_service.py` lines 9–10  
- **Issue:** `DB_PASSWORD` and `API_KEY` are committed plaintext; any repo reader gains production credentials.  
- **Fix:** Load from environment variables: `os.environ["DB_PASSWORD"]`, `os.environ["API_KEY"]`.

### SEC-008 · Hardcoded Secret — JWT signing key
- **File:** `src/api.py` line 9  
- **Issue:** `JWT_SECRET` is hardcoded; a leaked key allows forging authentication tokens for any user.  
- **Fix:** `JWT_SECRET = os.environ["JWT_SECRET"]` with a ≥256-bit random value.

### SEC-009 · Broken Authentication — static token issued at login
- **File:** `src/api.py` line 17  
- **Issue:** Every successful login returns `"token": "static-token-123"`, making session management illusory.  
- **Fix:** Issue a properly signed, time-limited JWT containing the authenticated user's identity.

### SEC-010 · Broken Access Control — `/user/<username>` exposes password hash anonymously
- **File:** `src/api.py` lines 20–27  
- **Issue:** No authentication check; response includes `password_hash`, enabling offline cracking.  
- **Fix:** Require a valid session; never include credential fields in API responses.

### QUA-001 · Duplicate Logic — `calculate_user_score` / `calculate_admin_score` are byte-for-byte identical
- **File:** `src/user_service.py` lines 80–118  
- **Issue:** Any change to scoring logic must be applied twice; divergence is inevitable.  
- **Fix:** Delete `calculate_admin_score`; use `calculate_user_score` everywhere, or accept a `role` parameter.

### QUA-002 · Duplicate Logic — `process_order` / `process_bulk_order` share full copy-paste body
- **File:** `src/order_service.py` lines 7–49  
- **Issue:** Entire pricing/tier logic duplicated; only `status` field differs.  
- **Fix:** Extract `_calculate_order(order_data, status)` helper; both public functions become one-liners.

### QUA-003 · High Complexity — `calculate_user_score` four-level nested conditionals
- **File:** `src/user_service.py` lines 80–98  
- **Issue:** Cyclomatic complexity ≈8; repeated `if bonus` inside each tier.  
- **Fix:** Use a lookup table `[(threshold, rate, bonus_rate)]` and apply bonus in a single post-step.

### QUA-004 · SRP Violation — `create_user` mixes hashing, SQL construction, and DB I/O
- **File:** `src/user_service.py` lines 43–53  
- **Issue:** Three unrelated concerns in one function; hashing step untestable without a live DB.  
- **Fix:** Extract `hash_password(password)` helper; manage connections via context manager.

### TST-001 · Zero Test Coverage — all 23 public functions untested
- **File:** All `sample_app/src/` files  
- **Issue:** Not a single test existed across the entire codebase before this review.  
- **Fix:** 31 pytest tests generated in `sample_app/tests/test_services.py` covering all major functions with mocked DB.

### DOC-001 · Zero Docstrings — all 24 public functions undocumented
- **File:** All `sample_app/src/` files  
- **Issue:** No function carried a docstring, making the API contract invisible.  
- **Fix:** Google-style docstrings generated for all 24 functions in `*_documented.py` companion files.

## 🟡 MEDIUM

### SEC-011 · Weak Crypto — unsalted MD5 for passwords
- **File:** `src/user_service.py` lines 30, 46  
- **Issue:** MD5 is cryptographically broken; no salt means rainbow-table attacks trivially crack all hashes.  
- **Fix:** Use `bcrypt`, `argon2-cffi`, or `hashlib.scrypt` with a per-user random salt.

### SEC-012 · Broken Access Control — `cancel_order` has no ownership check
- **File:** `src/api.py` lines 43–48  
- **Issue:** Any caller can cancel any order by supplying an arbitrary `order_id`.  
- **Fix:** Verify the authenticated user owns the order; return HTTP 403 otherwise.

### SEC-013 · Broken Access Control — `/order` POST requires no authentication
- **File:** `src/api.py` lines 36–41  
- **Issue:** Unauthenticated clients can place orders.  
- **Fix:** Add `@login_required` (or equivalent middleware) to the route.

### SEC-014 · Flask `debug=True` + `host="0.0.0.0"` in production
- **File:** `src/api.py` line 61  
- **Issue:** Exposes Werkzeug interactive debugger with remote code-execution shell.  
- **Fix:** `debug=False`; serve with Gunicorn/uWSGI; control via `FLASK_DEBUG` env var.

### QUA-006 · Magic Numbers — discount multipliers in `apply_discount`
- **File:** `src/order_service.py` lines 60–68  
- **Issue:** `0.90`, `0.80`, `0.50` unexplained; intent unclear to future maintainers.  
- **Fix:** `DISCOUNT_RATES = {"SAVE10": 0.10, "SAVE20": 0.20, "HALFOFF": 0.50}`; apply as `1 - rate`.

### QUA-007 · Magic Numbers — quantity thresholds in order processing
- **File:** `src/order_service.py` lines 14–17, 35–39  
- **Issue:** `100`, `50`, `0.9`, `0.95` appear as bare literals in two duplicated code blocks.  
- **Fix:** Define `BULK_TIER_LARGE`, `BULK_TIER_MEDIUM`, `DISCOUNT_LARGE`, `DISCOUNT_MEDIUM` constants.

### QUA-008 · Dead Code — `get_order_history` stub silently returns `None`
- **File:** `src/order_service.py` lines 56–58  
- **Issue:** `pass` body returns `None`; callers expecting a list get a silent `TypeError`.  
- **Fix:** `raise NotImplementedError("get_order_history is not yet implemented")`.

### QUA-009 · Missing Error Handling — bare dict key access in order functions
- **File:** `src/order_service.py` lines 9–11, 31–33  
- **Issue:** Missing keys raise `KeyError` with no informative message.  
- **Fix:** Validate with `pydantic` or explicit `.get()` checks returning HTTP 422 on invalid input.

### QUA-010 · Missing Error Handling — bare dict key access in `create_user_api`
- **File:** `src/api.py` lines 31–34  
- **Issue:** Incomplete JSON body raises unhandled `KeyError`.  
- **Fix:** Use `.get()` with null checks and return HTTP 400 on missing required fields.

### QUA-011 · Inconsistent Naming — `username` vs `user_id` across service functions
- **File:** `src/user_service.py` lines 16, 55, 65; `src/api.py` line 20–27  
- **Issue:** No consistent primary-key convention; some functions use string natural key, others use int surrogate.  
- **Fix:** Resolve `username → id` at the API boundary; use `user_id` consistently in internal service calls.

### QUA-012 · Inconsistent Patterns — DB connections never closed on exception
- **File:** `src/user_service.py` lines 12–78  
- **Issue:** `conn.close()` only runs on the happy path; exceptions cause connection leaks.  
- **Fix:** Use `with contextlib.closing(get_db_connection()) as conn:` throughout.

## 🟢 LOW

### SEC-015 · Missing Input Validation — `create_user` API
- **File:** `src/api.py` lines 29–34  
- **Issue:** No length or format checks; oversized inputs may cause unexpected DB behavior.  
- **Fix:** Enforce max-length constraints and reject unexpected characters; return HTTP 400 on violations.

### SEC-016 · Missing Input Validation — `process_order` / `process_bulk_order`
- **File:** `src/order_service.py` lines 7–11, 29–33  
- **Issue:** Negative or non-numeric `qty`/`price` produce invalid totals or unhandled exceptions.  
- **Fix:** Validate positive numeric types before processing; return HTTP 422 on invalid input.

### QUA-013 · Magic Number — hardcoded port `5000`
- **File:** `src/api.py` line 61  
- **Issue:** Port change requires source edit.  
- **Fix:** `port = int(os.environ.get("PORT", 5000))`

### QUA-014 · Unused Import — `import os` in `user_service.py`
- **File:** `src/user_service.py` line 4  
- **Issue:** `os` is imported but never used; adds noise and misleads readers.  
- **Fix:** Remove the import; re-add when env-variable-based secrets are introduced.

### QUA-015 · Inconsistent Return Style — bool vs truthy tuple
- **File:** `src/user_service.py` lines 26–33; `src/api.py` lines 16, 23–24  
- **Issue:** `authenticate_user` returns `bool`; `get_user` returns a raw DB row. Callers rely on tuple truthiness inconsistently.  
- **Fix:** Define a `User` dataclass; return it or `None` from all user-fetching functions; add type annotations.
